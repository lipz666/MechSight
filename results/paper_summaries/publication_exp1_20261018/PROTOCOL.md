# 实验 1：冻结协议（2026-10-18）

本实验只比较同一个模型的三种推理方法，不运行其他实验。

## 问题与组别

- A/direct：直接生成完整的 PGL 机理路径，随后进行三轮无工具自检；保留首次答案作为附加诊断，最后可解析答案为最终候选。
- B/agent_no_skills：冻结的 develop-2 Planner–Executor、动作校验、预演、审核和重规划；关闭 Planner skills。
- C/agent_skills79：同 B，使用本地已有 79 条 Planner skills，默认的结构召回、独立触发核验、证据检查与最多两条正文注入。

B−A 衡量当前 Agent 系统相对直接生成加自检的收益。C−B 衡量在同一个 Agent 系统中加入检索技能的收益。不能把 B−A 全部归因于单个模块，也不能把类别内新底物测试称为未见类别泛化。

## 数据与信息边界

- 来源：本地 core/mechfinder_merged_pgl_paths.core.jsonl，30576 条记录。
- 80 个新记录，40 个反应类别各两题，每题独立两次；三组共 480 条轨迹。
- 排除本地已有输出、技能代码/文档和来源期望表中可识别的既往反应 ID；还排除与这些记录规范化反应 SMILES 相同的反应。
- 用固定 seed=20261018 的哈希排序选题，不根据模型结果换题。适用范围预先限定为 2–10 个标注步骤、初态不超过 45 个重原子或 110 个总原子，以及可解析的常见整数/芳香键。
- 排除不能根据端点构建可执行完整初态的案例，例如目标凭空需要额外氢或 GT 引入未提供重原子。过滤计数保存在 manifest.json。候选检查在每类获得两题后停止，因此失败计数是扫描过程统计，不是全语料质量普查。
- 每个端点单独由 RDKit 推断氢数并统一全部显式化，不依据 GT 路径选择移动氢。端点氢对应关系仅依赖初态与目标态的各原子氢数，优先保留不变归属。所有重原子标签随机置换，氢标签统一重编；标签映射只在事后评分时使用。
- 推理输入仅包含匿名 case_id、初态和目标态；隐藏反应类别、名称、条件、GT 中间体与步数。
- inputs.jsonl 与 gold.jsonl 分离。run.py 不读取 gold.jsonl；只有 summarize.py 在推理后读取 GT。这里的“不读取 GT”针对运行时信息，不意味着上游 MechFinder 原始数据从未由模板/标注整理。
- 这是从已有开发语料重新划出的、记录和完整反应结构不重合的测试子集。尚未做骨架排重，也无法排除基础模型预训练污染。

## 模型与预算

- Base URL：https://LLM-GATEWAY-2.example/v1；请求模型 gemini-3.8-flash-high；显式 reasoning_effort=high，temperature=0.2。
- 接口响应 model 字段在连通性测试中为 gemini-3.8-flash-n；逐次记录实际字段，不据此推断底层权重或档位。
- 三组每条轨迹共同生成预算上限 98304 token，包括可观测 reasoning token；最多 64 次推理调用，最多 12 个执行步骤。
- A 每次完整路径最多输出 8192 token，最多四次；B/C 每次调用最多 4096 token。C 的技能检索、证据核验和协议修复都计入共同预算。
- 三组都得到同一套 PGL 表示/箭头/分步规范。A 也提供可从端点计算的结构差异，不提供模拟器或 GT 反馈。B/C 额外得到自身操作产生的状态反馈。
- 相同预算上限不等于实际消耗相同。分别报告生成 token、输入 token、总 token、reasoning token、调用数和耗时，不把更高成本隐去。
- 联调发现网关的 max_tokens 不能硬性限制单次请求的隐式思考 token。98304 因此实际是按返回用量停止后续调用的共同阈值；单次请求可能超额，必须另报超额条数，不能宣称严格等总计算量。这个接口限制在正式运行前已记录。
- API 密钥只从 OPENAI_API_KEY 环境变量读取，不保存到协议、代码或输出文件。

## 执行与评分

- 三组交错并发运行、固定打乱顺序；每条轨迹独立上下文；按条保存，可恢复。
- A 的候选路径在全部生成与自检结束后才由同一执行环境回放；首个无效动作之后停止，不把执行错误反馈给 A。主指标比较可执行的接受路径；额外保留未执行候选和初次答案，供诊断表示/执行损失。
- B/C 直接使用其真实已接受路径，保留被拒提案、预演及审核记录。
- 主指标：复用 develop.metrics 的归一化箭头 L1、L2、L3，H 标签匿名化；并报告 transfer F1。该指标不等价于电子数、价态、能垒或唯一真实机理的全面验证。
- 辅助诊断：重原子连接性及形式电荷的终态匹配、GT 中间体有序召回；忽略氢归属，不称为完整分子匹配。
- 所有有效完成轨迹均纳入主分母。基础设施中断单列为待补跑，必须补同题、不得换题或按正误筛选；未补齐前不发布完整实验结论。模型协议失败和预算耗尽属于方法结果。
- 比较采用同题同重复索引的配对差值，并按独立反应做 2000 次 cluster bootstrap，报告 95% 区间。附加类别层面的敏感性分析。有限样本不能保证检出 3–5 个百分点的小提升。
- 不使用同模型 LLM judge 为主实验打分；专家盲评尚未执行。
- 首题三组作为运行器连通性 smoke，允许修复纯基础设施/代码错误；不依据评分调 prompt 或重选样本。协议不变时其有效结果计入正式实验。

## 可复现文件

- manifest.json：数据源、输入、GT、冻结 Agent/skills 代码的 SHA-256 和排除记录。
- snapshot/：实际使用的 Agent 与 skills 快照。
- run_config.json：正式运行参数。
- 各组目录：每条轨迹结果及不含 API Key 的调用 trace。
- summary.json、scored_rows.jsonl、REPORT.md：事后评分与配对统计。

原有 40 个单元测试通过；新增实验相关 6 个测试通过。pytest 对含连字符目录 develop-2 的默认导入方式失败，改用该项目 unittest discover 后 40 个测试全部通过。

## 正式运行前的预算校准

联调仅检查传输、解析和 token 用量，没有计算或查看任何 GT 得分。网关 high 思考在单次规划中可产生 2 万以上生成 token，超过请求中可见输出 max_tokens；最初 32768 预算不足以容纳正常闭环。正式实验统一改为 98304 观测生成 token 的停止阈值，组间同值。旧联调保存在 preflight_budget_calibration/，不计入正式 480 条轨迹；不据此调 prompt、修改 skills 或换题。

## 接口恢复后的续跑

用户确认接口问题已解决后，于 2026-10-18 续跑原冻结实验；同一 run_config.json、同一输入和 Agent 快照，仍为 2 路并发。监督进程定期刷新报告并在退出时写入完整状态。此前被中断、没有完整结果的请求保留在 trace 或 infrastructure_attempts 中，不算独立重复。

## 用户要求提高并发

用户明确要求将并发从 2 提高到 100。仅修改调度 workers；输入、模型、温度、推理预算、重复次数及评分规则均不变。先停止旧监督器和运行器，再恢复队列；已完成结果保留并跳过，未完成轨迹保留旧 trace 后重跑原题。操作记录见 operational_changes.jsonl。
