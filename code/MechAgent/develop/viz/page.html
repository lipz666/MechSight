MechAgent · 可视化设计提案

推电子视图

机理预测的输出本身就是化学家熟悉的一种图：弯箭头。Agent 每一步吐出的 ElectronTransfer(source, target) 就是一支箭的起点和终点。 所以可视化不该是又一个力导向图或 JSON 折叠面板——结构式交给 RDKit 画，弯箭头叠在它的同一套坐标上， 再把 GT 路径和预测路径摆在一起对齐看。下面每一屏都用本仓库 outputs/gemini37_oracle_steps/full.jsonl 的真实 rollout 渲染。

为什么这么画

四条来自数据本身的约束

这些不是审美偏好，是 PGL 数据结构决定的。照着做，图就对了；不照做，怎么调色都别扭。

原子标号全程稳定

C101、O205 在整条路径里指同一个原子。所以整条机理只算一套坐标：把所有状态的键取并集布局一次，每一步复用。原子从此不会在步与步之间乱跳，动画自然连贯。

电子转移即弯箭头

source=('O1','lone_pair') → target=('O1','H302','new_sigma_bond')：起点是孤对，终点是尚不存在的键的中点。两个电子画双钩箭头，单电子画鱼钩。不需要再发明一套视觉语言。

GT 与预测同构

两边都是 ReactionTransformation 序列，可以逐 transfer 归一化比对。所以差异必须画成对齐带而不是两张分开的图——评测的三个层级 L1/L2/L3 正好是对齐带上三种松紧度。

剩余变化是可算的

state_diff 每一步都能算出「还差几个键没形成/没断」。这是整条轨迹唯一的客观进度条，比 Planner 自己说的「完成了」可信，应该常驻在画布下方。

主视图

单步推电子画布

结构由 RDKit 的 MolDraw2DSVG 绘制——键角、CH3/OH 缩写、 字体避让都归它管；氢默认折进重原子标签，参与本步反应时才单独现身。弯箭头由 GetDrawCoords 取得的仿射变换叠加上去，落点精确锚在原子上。 要移动的孤对画成一对点，箭头从点上出发；碳正碳负不写成 C+ 而是留作顶点、把电荷标在旁边，碳负还配上它应有的孤对。 只有反应中心的原子会亮出 PGL 标号——这是模型说话用的词，图上要能对得上。

实现路径

整套东西是离线渲染管线 + 一个零依赖前端，不需要在浏览器里跑化学库。

01

回放：把 action 序列变成状态序列

复用 standalone_chemistry.apply_action，从 initial_state_pgl 依次施加 GT 与已接受的预测动作，得到两串 ReactionState。回放失败的位置本身就是一个可视化信号（标注引入了初始态没有的原子，或预测的编辑非法）。

02

布局：并集图算一次坐标

把全路径出现过的原子取并集、键取并集（同一对原子取最高键级），建一个未 sanitize 的 RWMol，FastFindRings + Compute2DCoords。超价的并集键在布局前按度数裁掉，只影响排布不影响渲染。产物是 {原子标号: [x, y]}，写进 JSON。

03

绘制：RDKit 画结构，我们画箭头

每帧用 MolDraw2DSVG 出图，fixedBondLength 固定尺度，再按 GetDrawCoords 求出的仿射变换归一化到同一个世界坐标系——RDKit 会把每个分子重新居中，不归一化结构就会逐步跳动。箭头用二次贝塞尔，对弧线采样后按「离键和原子最远」挑边和弧度，所以长距离进攻不会横穿分子。颜色以哨兵色值出图，再替换成 CSS 变量，一次渲染同时适配深浅色。

04

对齐：复用评测已有的归一化

不要另写一套匹配逻辑。metrics.transfer_key 已经处理了端点方言（'O205' vs ('O205','lone_pair')）和氢匿名化，直接拿它的 key 做多重集配对，得到每个 transfer 的 shared / unique 标记。

05

产出：交互页与论文图共用一个渲染器

export_figure.py 把整条路径排成一幅图：每格一个状态，格间是反应箭头，全部按同一裁剪和同一尺度绘制，读者的眼睛只需跟着弯箭头走。白底黑线、可 --mono 出黑白版、可关掉 PGL 标号和反应中心底色。屏幕上看到的和投出去的是同一套几何，不存在「示意图和真实结果不一致」。
